## Issue #108 — "[SOLVED] ... TWO typos ... full decrypt + chain closure" — DEBUNKED

Claims the live-page blob has two typos, and that the password

```
matrixsumlistenterlastwordsbeforearchichoicethispasswordmatrixsumlist
```

decrypts it under EVP-BytesToKey/MD5 to 79 bytes containing `K_C1`, `K_C2`, `E_C`.

**Reproduced exactly here.** The blob in this repo is already byte-identical to the
issue's "corrected" blob, the password does decrypt under MD5, and the 79 output
bytes match the issue's published values.

**And it is a false positive.** Tested against the only criterion that matters:

```
printable fraction : 38.0%     random bytes expect 37.1%
distinct bytes     : 72 / 79   pure noise
PKCS7 pad          : 1         occurs by chance 1 time in 256
```

Neither `K_C1` nor `K_C2`, nor their XOR, modular sum, or either SHA-256
concatenation, derives to `1GSMG1JC9wtdSwfwApgj2xcmJPAwx7prBe` or
`17ucy1K9ZUAaoY6JVtM932W9jUp5LXfyHa` under compressed or uncompressed encoding.
`K_C1`'s public key does not match the public key the 2024-04-24 spend exposed
on-chain.

The 79 bytes are indistinguishable from random; the `K_C1 / K_C2 / E_C` labelling is
an arbitrary 32+32+15 slicing of noise. This is exactly the failure mode issue #106
documents for the earlier Half / Better-Half claims.

## What #108 was nonetheless worth

Its password is a **concatenation with a repeated token** — `matrixsumlist` appears
twice. Every sweep in this repo up to step 10 used *permutations*, which cannot
repeat a token, so that entire shape was unreachable across ~2.4 billion trials.

`tools/repcat.c` closes it: concatenations with repetition over a 20-token
vocabulary, lengths 1-5, 3,368,420 candidates. Coverage verified — the #108
password is generated by it.

```
variant A   3,368,420 candidates   26,947,360 trials   0 printable
variant B   3,368,420 candidates   26,947,360 trials   0 printable
```

## Also confirmed: the "one for one, four for one" reading

The README states this hints at **IBM EBCDIC code page 1141** — "1 for 1, 4 for 1"
concatenating to 1141. A numeric concatenation, which is the reading proposed to me

The digits were the wrong place to look; the number is a code page, not a code.

## Issue #103 — the phase-2 table, independently verified

Claims the Cosmic Duality decode's 4 trailing bytes resolve the phase-2 riddle
table `# X 2 S H 4 Y 0 Q B 15 #`.

**The premise is independently confirmed here.** `tools/dualite_chain.py`, written
before this issue was read, ends its run with `trailing 4 bytes: fc0c1b02` — the
same bytes. Read as signed 8-bit integers:

```
fc = -4    0c = 12    1b = 27    02 = 2
=>  X = -4,  H = 12,  Y = 27,  Q = 2
```

With the previously known S = 32 (Klingon arithmetic, 2 + 5x6) and B = -16 (Intel
model number), the table resolves to:

```
-4, 2, 32, 12, 4, 27, 0, 2, -16, 15
```

This genuinely links two stages treated as unrelated since 2019, and this repo's
own output corroborates the input to it.

Swept as key material — every join form, absolute values, mod 26 and mod 256,
a1z26 letters, hex bytes, and combinations with the page vocabulary, plus digests
of all of it — 3,768 candidates against all three blobs:

```
blob A (final)        3,768 candidates   30,144 trials   0 printable
blob B (final, alt)   3,768 candidates   30,144 trials   0 printable
phase 3.2 tail blob   3,768 candidates   30,144 trials   0 printable
```

Negative. As the issue's own author notes, the resolved table did not unlock a
blob for them either.
