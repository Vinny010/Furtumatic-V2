## Key Question 1: Has any ML system ever demonstrated out-of-sample accuracy above chance at predicting any bit of a private key from its public key or address? Strongest claimed example and its verification

### Takeaway
No. The strongest formally-written attempt found ("Mage", arXiv 2512.12483, Dec 2025) is itself a negative result: a 784M-parameter transformer trained on 100,000 (pubkey, privkey) pairs memorised the training set (99% train accuracy) while evaluation loss rose, and a second 350-epoch run on fresh random pairs showed "zero improvement" with flat loss. Every GitHub "predictor" repo examined reports no accuracy number at all. Nothing found anywhere reports out-of-sample per-bit accuracy statistically above 50%.

### Cited Findings
- Mage (Lily Erickson, arXiv 2512.12483, "Mage: Cracking Elliptic Curve Cryptography with Cross-Axis Transformers") is "a Cross-Axis Transformer retrofitted with special embedding and logit layers that allow it to process raw byte data", 784M parameters, hidden size 2048, 16 layers, 16 heads, "trained on a dataset of 100,000 key pairs with performance evaluated on a separate dataset of 38,200 pairs" (snippet only) — [arXiv 2512.12483 search snippet](https://arxiv.org/abs/2512.12483); [ResearchGate listing](https://www.researchgate.net/publication/398721685_Mage_Cracking_Elliptic_Curve_Cryptography_with_Cross-Axis_Transformers)
- Mage result: "The model demonstrated a capacity to memorize training data, achieving 99% accuracy on the training set, but as training loss decreased, evaluation loss increased, indicating overfitting"; the author writes the model "would make a far better Rainbow Table than an Elliptic Curve simulation" (snippet only) — [arXiv 2512.12483 HTML snippet](https://arxiv.org/html/2512.12483v1)
- Mage second experiment: "ran 350 epochs using only randomly generated keypair data with 100,000 samples each and saw zero improvement in the model, with loss staying flatline"; the paper "suggests that the model required significantly more data to learn a representation of the elliptic curve" (snippet only) — [arXiv 2512.12483 search snippet](https://arxiv.org/pdf/2512.12483)
- Despite the title, the search summary of the paper concludes the model "did not successfully recover private keys from public keys when tested beyond its training set" (snippet-level summary; the full PDF could not be fetched to verify the exact wording or the curve bit-length used) — [arXiv 2512.12483](https://arxiv.org/abs/2512.12483)
- Secondary coverage headlined "Mage Enables Cracking Of Elliptic Curve Cryptography, Risks To Modern Internet Security" — a headline unsupported by the paper's own reported numbers (site unreachable; headline seen in search results only) — [Quantum Zeitgeist](https://quantumzeitgeist.com/security-mage-enables-cracking-elliptic-curve-cryptography-risks-modern/)
- ufodia/Bitcoin-Private-Key-Predictor (TensorFlow MLP mapping public key -> private key, trained on random pairs, e.g. "epochs=3000, batch_size=512", MAE/MSE loss): README gives "No specific accuracy metrics or claimed results" and states "Predicting private keys associated with real Bitcoin addresses is computationally infeasible due to the immense key space, and this project does not aim to bypass security features of cryptographic systems." 2 stars, 2 forks — [GitHub ufodia/Bitcoin-Private-Key-Predictor](https://github.com/ufodia/Bitcoin-Private-Key-Predictor)

- btc-room101/bitcoin-rnn (LSTM "to associate public bitcoin addresses, with private keys", training pairs generated by mk-privaddr-pair.py): "No specific accuracy metrics, performance data, or successful results are provided"; author calls it a "toy example" and says "true production requires huge training sets, and various alternate representations of bitcoin address abstraction". 37 stars, 30 forks, 2 commits — [GitHub btc-room101/bitcoin-rnn](https://github.com/btc-room101/bitcoin-rnn)

- HomelessPhD/BTC32 (103 stars; statistical analysis of the puzzle keys' normalised positions "alpha" for keys #1-#63): autocorrelation testing "showing no linear relationships or patterns"; the author warns that SVMs/neural nets "could just memorize the data instead of retrieving the logic behind the data" and that "a model you are using for prognosis should have a number of parameters less than a number of observations"; "No successful ML/statistical approach is documented" — [GitHub HomelessPhD/BTC32](https://github.com/HomelessPhD/BTC32)
- The BTC32 README quotes the puzzle creator: "There is no pattern. It is just consecutive keys from a deterministic wallet" — [GitHub HomelessPhD/BTC32](https://github.com/HomelessPhD/BTC32) (original bitcointalk post unreachable; the canonical thread is [bitcointalk topic 1306983](https://bitcointalk.org/index.php?topic=1306983.0))
- Theoretical ceiling: Takhanov et al., "Intractability of Learning the Discrete Logarithm with Gradient-Based Methods" (ACML 2023, PMLR 222:1321-1336) prove that for the parity bit of the discrete logarithm in a prime-order cyclic group "the gradient of the loss function concentrates around a fixed point, independent of the logarithm's base used", which "leads to a restricted ability to learn the parity bit efficiently using gradient-based methods, irrespective of the complexity of the network architecture being trained" (snippet only) — [PMLR v222 takhanov24a](https://proceedings.mlr.press/v222/takhanov24a.html); [arXiv 2310.01611](https://arxiv.org/abs/2310.01611)

### Inferences
- The only quantified "claimed result" in the whole space (Mage's 99%) is a training-set memorisation figure; its held-out behaviour (rising eval loss, flat loss on fresh data) is consistent with chance-level generalisation, i.e. a rainbow table of 100k entries, not a learned inverse.
- Even the single low-order bit (parity of the discrete log) is provably out of reach of gradient methods (Takhanov et al.), so a positive per-bit result would contradict a published theorem, not merely folk wisdom. Note the theorem is about gradient-based training; it does not by itself rule out non-gradient methods, but no non-gradient method with a positive result was found either.
- Hobby repos uniformly stop at "proof of concept" and never publish a held-out accuracy, which is the signature of a negative result the author chose not to report.

### Gaps
- Mage's full text (curve size, whether secp256k1 or a toy curve, exact eval accuracy in bits) could not be verified because arxiv.org, alphaxiv, awesomepapers.io and Semantic Scholar were blocked; the numbers above are from search snippets of the paper's own HTML.
- No replication or independent debunk of Mage was found (searching "Mage cross-axis transformer criticism" returned only the paper and its mirrors).
- No Hugging Face model card for a private-key predictor was found via search (HF search results returned only trading LLMs such as agarkovv/CryptoTrader-LM and mpetitguillaume/cryptoGPT); huggingface.co itself was unreachable so an on-platform search could not be run. No Kaggle notebook on key prediction was found (all Kaggle hits were price-prediction notebooks).

## Key Question 3: arXiv/academic papers on neural cryptanalysis of SHA-256/RIPEMD-160 or of EC scalar multiplication, and their conclusions

### Takeaway
The legitimate literature shows learned attacks work only on drastically weakened primitives: Gohr's neural distinguisher reaches 92.9% on 5-round Speck32/64 but only 51.4% at 8 rounds (of 22); the "fuzzy bits" paper inverts only a few rounds of MD5/SHA-1/SHA-256/Keccak; SALSA recovers LWE secrets only for n<=128 with Hamming weight <=4; and Mage fails on the EC map. Two theory papers by Takhanov et al. explain why: gradient variance for discrete-log-parity and modular-multiplication classes is negligible.

### Cited Findings
- Gohr (CRYPTO 2019, "Improving Attacks on Round-Reduced Speck32/64 Using Deep Learning", ePrint 2019/037): neural distinguishers N5-N8 achieved accuracies of 0.929, 0.788, 0.616 and 0.514 for 5-8 rounds, versus 0.911, 0.758, 0.591 and 0.512 for classical DDT-based distinguishers; key-recovery attacks reach 11 and 12 rounds and "reduce the remaining security of 11-round Speck32/64 to roughly 38 bits" (snippet only) — [ePrint 2019/037](https://eprint.iacr.org/2019/037.pdf); [Cybersecurity (Springer) 2023 framework paper](https://cybersecurity.springeropen.com/articles/10.1186/s42400-023-00176-7)
- Follow-up literature confirms the ceiling: "the accuracy of existing neural distinguishers remains limited for high-round-reduced cryptosystems" — [Scientific Reports 2025, multiple-ciphertext-pair distinguishers for Speck and Simon](https://www.nature.com/articles/s41598-025-98251-1); [Computer Journal 2023](https://academic.oup.com/comjnl/article/66/6/1419/6545266); [arXiv 2301.11601 Simeck32/64](https://arxiv.org/pdf/2301.11601)
- Hash inversion: "Using fuzzy bits and neural networks to partially invert few rounds of some cryptographic hash functions" (arXiv 1901.02438) trains networks "to predict the message that has a given hash for standard cryptographic hash functions including MD5, SHA1, SHA2-256, and SHA3/Keccak with small numbers of reduced rounds", by generalising the functions to continuous "fuzzy bits" so they become differentiable; a related snippet describes tests on SHA-256 at "4 rounds with 128-bit messages" (snippet only; full PDF unreachable) — [arXiv 1901.02438](https://arxiv.org/abs/1901.02438)
- Practitioner note from a SAT/MILP/belief-propagation preimage-attack repo: "backpropagation through hash functions is quite slow due to the complex computational graph created by the hash function, involving slicing and moving of individual tensor elements (bits)" — [GitHub secp8x32/preimage-attacks](https://github.com/secp8x32/preimage-attacks)
- Baseline fact used by that literature: "there are currently no known classical pre-image attacks against any of the SHA-2 algorithms which are faster than brute force" (snippet from quantum-preimage cost paper) — [arXiv 1603.09383](https://arxiv.org/pdf/1603.09383)
- No paper attacking RIPEMD-160 with neural networks was found in any search.
- EC scalar multiplication: the only paper found is Mage (see Q1), which reports memorisation and no generalisation — [arXiv 2512.12483](https://arxiv.org/abs/2512.12483)
- Theory, discrete log: Takhanov, Tezekbayev, Pak, Bolatov, Kadyrsizova, Assylbekov, ACML 2023 (PMLR 222:1321-1336) — the gradient for learning the DL parity bit "concentrates around a fixed point, independent of the logarithm's base", giving "restricted ability to learn the parity bit efficiently using gradient-based methods, irrespective of the complexity of the network architecture"; proof via the Boas-Bellman inequality and approximate orthogonality of the parity-bit functions (snippet only) — [PMLR](https://proceedings.mlr.press/v222/takhanov24a.html); [arXiv 2310.01611](https://arxiv.org/abs/2310.01611)
- Theory, modular arithmetic: Takhanov et al., "Gradient Descent Fails to Learn High-frequency Functions and Modular Arithmetic", Machine Learning 114(4), 2025 — classes such as x -> ax+b mod p "containing a large number of approximately orthogonal elements are known to be hard to learn by the Statistical Query algorithms" and the same hardness "re-emerged in a theory of gradient-based optimization of neural networks", quantified by gradient variance over a random target (abstract snippet) — [arXiv 2310.12660](https://arxiv.org/abs/2310.12660); [Springer Machine Learning 2025](https://link.springer.com/article/10.1007/s10994-025-06747-8)
- Hardness-of-learning from cryptography: Daniely & Vardi, "From Local Pseudorandom Generators to Hardness of Learning" (COLT 2021) derive hardness of learning simple function classes from local PRGs — [PMLR v134 daniely21a](https://proceedings.mlr.press/v134/daniely21a/daniely21a.pdf)
- The one genuinely successful ML attack on a public-key primitive is on lattices, not curves: SALSA (Wenger et al., NeurIPS 2022, ePrint 2022/935) "trains transformers to perform modular arithmetic and combines half-trained models with statistical cryptanalysis", recovering secrets "for LWE problems with dimension n<=128 and Hamming weight <=4" (sparse binary secrets); the authors note "scaling d [secret density] being a much harder problem than scaling n" (snippet only) — [ePrint 2022/935](https://eprint.iacr.org/2022/935); [arXiv 2207.04785](https://arxiv.org/abs/2207.04785); successors Salsa Picante [ePrint 2023/340](https://eprint.iacr.org/2023/340.pdf) and Salsa Verde [arXiv 2306.11641](https://arxiv.org/pdf/2306.11641)
- Adjacent legitimate ML+crypto work that is often mis-cited as "AI breaks crypto": neural-inspired integral cryptanalysis (arXiv 2505.10790), where "the motivation for introducing neural networks into cryptanalysis is precisely to uncover more non-random features from a limited amount of data" — [arXiv 2505.10790](https://arxiv.org/pdf/2505.10790); cryptanalytic *extraction of neural networks* (the reverse direction) — [arXiv 2410.05750](https://arxiv.org/pdf/2410.05750), [arXiv 2609.14379](https://arxiv.org/pdf/2609.14379)
- Non-attack use of "neural + ECDSA" that search engines surface: "Towards ECDSA key derivation from deep embeddings" (arXiv 1711.04069) derives keys *from* CNN embeddings as a biometric KDF, not an attack — [arXiv 1711.04069](https://arxiv.org/pdf/1711.04069)

### Inferences
- The Gohr line is the strongest positive result in neural cryptanalysis and it degrades to near-coin-flip (51.4%) by 8 of 22 rounds on a 32-bit toy cipher; extrapolating to 64 rounds of SHA-256 or to a 256-bit group operation has no empirical support anywhere in the literature.
- SALSA is the credible "dissent": ML did break a real hardness assumption in tiny, structured parameter regimes (sparse secrets, small n) because LWE has additive structure and noise; ECDLP on secp256k1 has neither a small-secret variant in use nor a noise channel, and Mage's flat loss is consistent with the Takhanov theorems.
- The report can safely state that no peer-reviewed or preprint result shows a learned inverse of SHA-256, RIPEMD-160 or secp256k1 scalar multiplication beyond a handful of rounds / memorisation.

### Gaps
- Exact per-round accuracies from the fuzzy-bits paper (1901.02438) and the curve size used in Mage could not be read because arxiv.org and ar5iv were blocked.
- No survey paper specifically titled around "neural networks cannot learn random oracles" was found; the closest theory sources are the Takhanov and Daniely-Vardi papers above.

## Key Question 4: What do cryptographers say about why learning-based attacks cannot work against a secure one-way function, and is there any credible dissent?

### Takeaway
The standard explanation is that a secure PRF/one-way function has no exploitable redundancy or smooth structure, so a learner "has nothing to grip", and that any efficient learner that generalised would constitute a distinguisher and thus break the pseudorandomness assumption; the Takhanov theorems make this concrete for gradient methods on discrete-log parity. The only credible dissent is scoped: ML-assisted cryptanalysis of reduced-round ciphers (Gohr) and of small/sparse LWE instances (SALSA), plus side-channel and password-guessing applications.

### Cited Findings
- Explanation surfaced under Schneier-related searches: "Machine learning works by exploiting redundancy, the low-entropy structure in data; done right, ciphertext has no such redundancy. It is as random as data compressed to the limit and then XORed with a one-time pad, so the model has nothing to grip." and "any efficient algorithm's success at distinguishing or inverting the cipher reduces to breaking that pseudorandomness, which is built to be infeasible." (site unreachable; snippet only) — [postquantum.com, "Why AI Cannot Break Modern Encryption"](https://postquantum.com/ai-security/ai-break-encryption/)
- Schneier's position as summarised in the same search: AI "will sharpen some attack vectors but does not change the strength of the cipher itself: security relies on the mathematics of the encryption algorithm rather than on easily exploitable flaws" (snippet only) — [Schneier on Security, "Teaching a Neural Network to Encrypt" (2016)](https://www.schneier.com/blog/archives/2016/11/teaching_a_neur.html)
- Matthew Green's PRF/PRP explainer is the standard reference for why pseudorandom functions are indistinguishable from random to any efficient algorithm (learners included) — [A Few Thoughts on Cryptographic Engineering, "PRFs, PRPs and other fantastic things" (2023)](https://blog.cryptographyengineering.com/2023/05/08/prfs-prps-and-other-fantastic-things/)
- Theory foundation: "Pseudorandom generators exist if and only if one-way functions exist" (Håstad-Impagliazzo-Levin-Luby line) — [ACM STOC 1985, "One-way functions and pseudorandom generators"](https://dl.acm.org/doi/10.1145/22145.22185); [Springer, "Pseudorandom Generators from One-Way Functions: A Simple Construction for Any Hardness"](https://link.springer.com/chapter/10.1007/11681878_23)
- "Learning from pseudo-randomness with an artificial neural network" (arXiv 1801.01117) is an early empirical paper in this genre — [arXiv 1801.01117](https://arxiv.org/pdf/1801.01117) (content not fetched; title only)
- Practitioner statements on the Bitcoin side: "Deriving the private key from the public key is computationally hard because Bitcoin relies on asymmetric cryptography ... this process is mathematically one-way"; addresses add SHA-256 then RIPEMD-160 so "you would need to reverse multiple cryptographic hash functions" (search-summary of Bitcoin-education pages) — [D-Central, "Can We Brute Force a Bitcoin Private Key?"](https://d-central.tech/can-we-bruteforce-a-bitcoin-private-key/); [Bitcoin.com News](https://news.bitcoin.com/how-hard-is-it-to-brute-force-a-bitcoin-private-key/)
- Scale statement often quoted alongside: NIST-level 256-bit ECC gives ~128-bit security (~2^128 steps) and "A complete Rainbow Table for all known public-to-private key mappings for a 256-bit curve would require approximately 7.41×10^57 zettabytes of data"; "There is no known sub-exponential algorithm which solves the Elliptic Curve Discrete Logarithm Problem in general" (snippets attributed to the Mage paper's own background section and related arXiv pages) — [arXiv 2512.12483](https://arxiv.org/pdf/2512.12483)
- Polygon co-founder Mihailo Bjelic, July 2025: "It's not possible to crack Bitcoin private keys with AI, this is fake news and it doesn't even make sense." (snippet only) — [CryptoTimes fact-check](https://www.cryptotimes.io/2025/07/06/ai-tools-have-cracked-bitcoin-private-keys-fact-check/)
- Credible dissent (scoped): SALSA/Picante/Verde show transformers can recover LWE secrets at n<=128, sparse secrets — [ePrint 2022/935](https://eprint.iacr.org/2022/935); Gohr's distinguishers beat classical DDT distinguishers on reduced-round Speck — [ePrint 2019/037](https://eprint.iacr.org/2019/037.pdf); Mage's own stated hypothesis that "if a latent pattern in the ECDLP exists" a universal approximator could find it — with its own experiments finding none (snippet) — [arXiv 2512.12483](https://arxiv.org/abs/2512.12483)

### Inferences
- The cryptographers' argument and the learning-theory argument are the same argument seen from two sides: a learner that generalises on (pubkey, privkey) pairs is an efficient distinguisher/inverter, which the hardness assumption forbids; the Takhanov results show that for gradient descent this manifests as a gradient that is essentially independent of the target.
- Dissent exists only where the primitive has exploitable structure (few rounds, sparse secrets, noise), which secp256k1 and full SHA-256/RIPEMD-160 lack; nothing found argues otherwise.

## Key Question 5: 2025-2026 "AI cracked Bitcoin" news stories and how they resolved; the scam/malware angle around "key finder" tools

### Takeaway
Two viral episodes: (1) July 2025, when eight 14-year-dormant wallets moved 80,000 BTC (~$8.6B) and an influencer claimed AI had cracked their keys — analysts and Polygon's Bjelic rejected it, and the movements were judged owner-initiated; (2) May 2026, "Claude cracked a Bitcoin wallet" — Claude helped locate an old wallet backup / run a password search (~3.5 trillion guesses reported), the wallet was opened with the owner's own password, and no curve or hash was broken. Separately, "key finder"/"seed phrase finder" tools are a documented malware and social-engineering vector (Kaspersky's GitVenom: ~$456K-$485K BTC stolen via fake GitHub projects).

### Inferences
- Every 2025-2026 "AI cracked Bitcoin" story reduces to one of: (a) owner-initiated movement of old coins, (b) AI-assisted *password/file* recovery of the owner's own wallet, or (c) AI-accelerated exploitation of software bugs — none is key inference from public data.
- The "key finder" ecosystem is economically rational only as (i) malware delivery (GitVenom-style), (ii) paid "AI finder" subscriptions, or (iii) seed-phrase bait; the READMEs' silence on hit rates is consistent with an expected hit rate of effectively zero.
